# BODA VMS Train Worker 설치 가이드

문서 버전 v1.0 (2026-09-10) · 대상: 공장 안 GPU PC 에 학습 워커를 설치하는 엔지니어 · 근거: `MLOps Phase3 학습 워커 설계 명세.md` §6·§10

학습 워커는 MLOps 관리 서버에서 학습 작업을 받아 이 PC 의 GPU 로 학습하고 결과 모델을 서버에 올리는 Windows 서비스입니다.
검사 라인 PC 에는 설치하지 않습니다. 라인 PC 는 GPU 없이 CPU 로 추론만 하고, 학습은 공장에 한 대 두는 GPU PC 가 맡습니다.

## 1. 준비물

| 항목 | 요구 | 확인 방법 |
|---|---|---|
| OS | Windows 10/11 64-bit 또는 Windows Server 2019+ | |
| GPU | NVIDIA, VRAM 8GB 이상 권장 | `nvidia-smi` 가 GPU 를 보여야 함 |
| 드라이버 | CUDA 12.4 를 지원하는 NVIDIA 드라이버 (≥ 550) | `nvidia-smi` 오른쪽 위 `CUDA Version: 12.4` 이상 |
| Python | **3.12 (64-bit), "모든 사용자용" 설치** | `py -3.12 -V` → `Python 3.12.x` |
| 디스크 | 여유 50GB 이상 (venv 약 8GB + 데이터셋 캐시) | |
| 네트워크 | 관리 서버(기본 5310/TCP)로 **나가는** 연결만 | 워커는 받는 포트가 없어 방화벽 예외가 필요 없음 |
| 서버 | BODA VMS MLOps 서버가 떠 있고 관리자 계정이 있음 | 브라우저로 `http://<서버>:5310` 접속 |

Python 은 python.org 설치 프로그램에서 **"Install for all users"** 를 켜고 설치하세요. 워커는 서비스 계정(LocalSystem)으로 돌기 때문에
현재 사용자 전용으로 설치한 파이썬은 못 찾을 수 있습니다. 설치 마법사의 "Python 3.12" 줄이 "현재 사용자 전용 설치" 라고 표시되면 이 경우입니다.
(워커는 PEP 514 레지스트리 `HKLM\Software\Python\PythonCore\3.12` → `py` 런처 → PATH 순서로 파이썬을 찾습니다.)

설치 프로그램(.NET 런타임 포함, self-contained)은 약 30MB 이고 .NET 을 따로 설치할 필요가 없습니다.

## 2. 토큰 발급 (관리 화면)

1. 관리 화면 ▸ **워커** ▸ **[워커 추가]** (Admin 권한).
2. 이름(예: `GPU-01`)과 지원 작업 유형을 고르고 만들면 `wk_` 로 시작하는 토큰이 **한 번만** 표시됩니다. 복사해 두세요.
3. 잃어버렸으면 워커 카드의 **[토큰 재발급]** 으로 새 토큰을 받고 워커를 다시 configure 합니다.

토큰은 워커 전용 서비스 계정입니다. 데이터셋 내보내기·사전학습 파일·스크립트·작업 보고만 할 수 있고 레시피나 생산 이력에는 닿지 않습니다.

## 3. 설치

### 3.1 마법사로

`BODA-VMS-TrainWorker-<버전>.msi` 를 실행합니다.

1. 설치 폴더 (기본 `C:\Program Files\BODA Vision AI\BODA VMS TrainWorker`)
2. **워커 연결 설정**
   - 관리 서버 주소: `http://<서버 IP>:5310`. 관리 서버와 같은 PC(올인원)면 `http://localhost:5310`
   - 워커 토큰: 2 에서 복사한 `wk_…`
   - 워커 이름: 관리 화면에 보일 이름 (기본 컴퓨터 이름)
   - "GPU 없이 CPU 로만 동작 허용" 은 시험용입니다. 현장에서는 끕니다.
   - 아래 "Python 3.12" 줄에서 파이썬이 잡혔는지 확인합니다.
3. 설치.

설치가 끝나면 서비스 `BodaVmsTrainWorker` 가 **자동(지연 시작)** 으로 등록되고 바로 시작됩니다.
서버 주소·토큰을 비워 두고 설치했다면 서비스는 등록만 되고 멈춘 상태입니다. 3.3 을 따라 나중에 설정합니다.

### 3.2 무인 설치

```bat
msiexec /i BODA-VMS-TrainWorker-0.1.0.msi /qn ^
  SERVERURL=http://192.168.0.10:5310 WORKERTOKEN=wk_xxxxxxxx WORKERNAME=GPU-01
```

옵션: `WORKERCPU=1` (CPU 전용 허용), `INSTALLFOLDER="D:\Apps\TrainWorker"`.
상세 로그(`/l*v`)를 남겼다면 토큰이 명령줄 형태로 찍힐 수 있습니다. 그 로그를 밖에 내보냈다면 토큰을 재발급하세요.

### 3.3 나중에 설정하기 / 설정 바꾸기

관리자 명령 프롬프트에서:

```bat
cd "C:\Program Files\BODA Vision AI\BODA VMS TrainWorker"
BODA.VMS.MLOps.TrainWorker.exe configure --server http://192.168.0.10:5310 --token wk_xxxxxxxx --name GPU-01
sc start BodaVmsTrainWorker
```

`configure` 옵션:

| 옵션 | 뜻 |
|---|---|
| `--server <url>` | 관리 서버 주소 (필수) |
| `--token <wk_…>` | 워커 토큰 (필수, DPAPI 로 암호화해 저장) |
| `--name <이름>` | 관리 화면 표시 이름 |
| `--python <python.exe>` | venv 부트스트랩 대신 이미 있는 파이썬(torch 설치됨)을 쓴다 |
| `--wheels <폴더>` | 오프라인 wheel 번들 폴더 (5 참조) |
| `--cache <폴더>` | venv·데이터셋·작업 캐시 루트 (기본 `%ProgramData%\BODA VMS TrainWorker`). 데이터셋이 크면 넉넉한 드라이브로 |
| `--gpu <n>` | 쓸 GPU 인덱스 (기본 0) |
| `--cpu` | CUDA 없어도 작업을 받는다 (시험용) |

설정 파일은 `%ProgramData%\BODA VMS TrainWorker\worker.json` 입니다. 바꾼 뒤에는 서비스를 다시 시작합니다.

## 4. 첫 시작에 일어나는 일

서비스가 처음 뜨면 파이썬 환경을 스스로 준비합니다. 관리 화면에 워커가 나타나기까지 시간이 걸리는 이유입니다.

1. 기반 Python 3.12 를 찾아 `%ProgramData%\BODA VMS TrainWorker\venv` 를 만든다.
2. 허용 목록(`scripts\requirements-allowlist.txt`)의 패키지를 설치한다. **온라인이면 PyPI 와 PyTorch cu124 인덱스에서 약 6GB 를 받습니다. 네트워크에 따라 10~40분.** 오프라인 번들이면 수 분.
3. `worker_diag.py` 로 자기진단: CUDA 사용 가능 여부, GPU 이름·메모리, 패키지 버전, 스크립트 해시.
4. 서버에 등록. 진단이 통과하면 **Online**, 실패 항목이 있으면 **Disabled(진단 실패)** 로 표시되고 작업을 받지 않습니다.

진행 상황은 로그 `%ProgramData%\BODA VMS TrainWorker\logs\worker-yyyyMMdd.log` 에서 봅니다.

설치 직후 GPU 가 잡혔는지 바로 보려면 (서비스와 별개로 같은 환경을 검사합니다):

```bat
cd "C:\Program Files\BODA Vision AI\BODA VMS TrainWorker"
BODA.VMS.MLOps.TrainWorker.exe diag
```

```
python      : C:\ProgramData\BODA VMS TrainWorker\venv\Scripts\python.exe
cuda        : 사용 가능  NVIDIA GeForce RTX 4060 Laptop GPU 8187MB 12.4
packages    : anomalib 1.2.0, onnxruntime 1.29.0, torch 2.6.0+cu124, torchvision 0.21.0+cu124, transformers 5.17.0, ...
진단 결과   : 정상 — 서버에 등록되면 작업을 받습니다
```

`cuda : 없음` 인데 `torch 2.x.x+cpu` 로 보이면 드라이버 문제가 아니라 CPU 빌드 torch 가 깔린 것입니다. 6 을 보세요.

## 5. 폐쇄망(오프라인) 설치

인터넷이 없는 공장에는 wheel 번들이 든 `-offline.msi` 를 씁니다.

인터넷이 되는 PC(같은 조건: Windows x64 · Python 3.12)에서:

```powershell
cd D:\Repo\BODA.VMS.MLOps
.\scripts\make-wheel-bundle.ps1          # → src\BODA.VMS.MLOps.TrainWorker.Setup\WheelBundle\ (약 6GB)
dotnet build src\BODA.VMS.MLOps.TrainWorker.Setup -c Release
# → bin\Release\BODA-VMS-TrainWorker-<버전>-offline.msi
```

스크립트는 마지막에 임시 venv 를 만들어 번들만으로 전체 설치가 되는지 확인하고, torch 가 CUDA 빌드(`+cu124`)인지 검사합니다.
`-offline.msi` 는 wheel 을 `[설치 폴더]\wheels` 에 함께 놓고 configure 에 `--wheels` 를 자동으로 넘기므로 현장에서는 3 과 똑같이 설치하면 됩니다.

사전학습 가중치도 인터넷에서 받지 않습니다. 워커는 `HF_HUB_OFFLINE=1` 로 돌고 서버의 **사전학습 미러**(관리 화면 ▸ 사전학습)에서만 받습니다.
작업을 제출할 때 사전학습 자산을 고르지 않으면 워커에서 "사전학습 모델 로드 실패 … couldn't connect to huggingface.co" 로 실패합니다.
미러에 자산을 올려 두고(예: `dfine-small-obj2coco` 의 `config.json` + `model.safetensors`) 작업에 지정하세요.

## 6. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 관리 화면에 워커가 안 나타남 | venv 부트스트랩 진행 중 | 로그에 `venv 부트스트랩 시작` 뒤 pip 출력이 이어지면 기다린다 (온라인 10~40분) |
| 로그에 `기반 파이썬 3.12(또는 3.11)을 찾을 수 없습니다`, 60초마다 재시도 (그 위에 `버전이 맞지 않는 파이썬은 건너뜁니다 … (3.14)` 가 있을 수 있음) | Python 3.12 미설치 또는 현재 사용자 전용 설치. PATH 에 다른 버전(3.14 등)만 있음 | Python 3.12 를 "모든 사용자용" 으로 설치 → 서비스 재시작. 또는 `configure --python <python.exe>` 로 torch 가 있는 파이썬을 직접 지정 (설치 폴더가 사용자 홈이어도 서비스 계정이 읽을 수 있으면 됨) |
| 로그에 `완료되지 않은 venv 를 지우고 다시 만듭니다` | 지난 부트스트랩이 pip 도중 실패 | 정상 동작. 워커가 스스로 다시 만든다. 반복되면 그 아래 pip 오류를 본다 |
| `워커 토큰이 없습니다` 로 서비스가 곧 멈춤 | 설정 없이 설치 | 3.3 |
| Disabled: `torch.cuda.is_available() == False` | 드라이버가 CUDA 12.4 미만이거나 GPU 없음 | 드라이버 갱신. GPU 없는 시험 PC 는 `--cpu` |
| Disabled: `torch 가 CUDA 빌드가 아닙니다 (2.x+cpu)` | pip 가 PyPI 의 CPU wheel 을 고름 | `requirements-allowlist.txt` 의 cu124 인덱스·torch 버전 범위 확인 후 venv 폴더를 지우고 서비스 재시작 |
| Disabled: `transformers >= 4.52 필요` / `import 실패` | 허용 목록 설치 일부 실패 | 로그의 pip 오류 확인 → venv 폴더 삭제 후 재시작 |
| 서비스는 Online 인데 작업이 `Preparing` 에서 실패 | 디스크 부족 또는 서버 export 실패 | 로그의 `데이터셋 다운로드` 줄과 디스크 여유(데이터셋 ×3 필요) 확인 |
| 작업 실패 `사전학습 모델 로드 실패 … huggingface.co` | 작업에 사전학습 자산 미지정 | 미러에 자산 등록 후 작업 재제출 (5) |
| 서비스 계정에서 CUDA 가 안 잡힘 (콘솔 `diag` 는 정상) | 세션 0 에서 GPU 접근을 막는 드라이버/정책 | 서비스 속성 ▸ 로그온 ▸ 지정 계정(로컬 관리자)으로 바꾸고 재시작. 캐시 폴더 권한도 그 계정에 준다 |
| `401`/`403` 이 반복되고 워커가 Disabled | 토큰 회수·재발급됨 또는 서버 프로토콜 불일치 | 관리 화면에서 토큰 재발급 → `configure --token` → 재시작. 워커 버전이 낮으면 MSI 업그레이드 |

venv 를 다시 만들려면 서비스를 멈추고 `%ProgramData%\BODA VMS TrainWorker\venv` 를 지운 뒤 시작합니다. 데이터셋 캐시(`datasets\`)는 그대로 둬도 됩니다.

## 7. 업그레이드 · 제거

- **업그레이드**: 새 MSI 를 실행하거나 `msiexec /i 새버전.msi /qn`. 기존 `worker.json` 이 있으면 그대로 쓰고 서비스를 다시 시작합니다. venv·캐시는 유지됩니다.
- **제거**: 앱 및 기능에서 제거. 서비스와 프로그램 파일만 지워지고 `%ProgramData%\BODA VMS TrainWorker` (설정·venv·캐시·로그)는 남습니다. 완전히 지우려면 그 폴더를 직접 삭제합니다.
- 워커 PC 는 백업 대상이 아닙니다. 결과 모델·지표는 서버 스토리지에 있습니다.

## 8. 올인원 구성 (관리 서버 = 워커 PC)

소규모 사이트는 GPU PC 한 대에 관리 서버와 워커를 함께 둡니다. 서버를 먼저 띄운 뒤 같은 PC 에 이 MSI 를 설치하고 서버 주소를 `http://localhost:5310` 으로 지정합니다.
라벨링 PC 로도 같이 쓰면 브라우저는 `http://localhost:5310` 을 엽니다.

## 부록. 이 PC 에서 확인된 값 (2026-09-10 실증)

RTX 4060 Laptop(8GB) · Windows 11 · Python 3.12.10 · 온라인 venv 부트스트랩 → `torch 2.6.0+cu124 · torchvision 0.21.0+cu124 · transformers 5.17.0 · rfdetr 1.10.1 · anomalib 1.2.0`.
로컬 서버에 Detection 작업(D-FINE small, 2장·2 에폭)을 제출해 워커가 받아 학습·ONNX 검증·Candidate 등록까지 약 50초.

MSI 0.1.0 실제 설치(무인, SERVERURL/WORKERTOKEN): 서비스 `BodaVmsTrainWorker` LocalSystem·자동(지연) 등록, `worker.json` 생성, 즉시 시작.
이 PC 의 Python 3.12 는 사용자 전용 설치라 서비스는 PATH 의 3.14 를 잡아 torch 설치에 실패했다(→ 위 §6 첫 두 줄의 근거). `configure --python` 으로 기존 venv 를
지정하니 **세션 0(LocalSystem)에서도 CUDA 가 잡혀 Online** 으로 등록됐고, 서비스로 도는 워커가 3 에폭 작업을 받아 Candidate 까지 등록했다(약 55초).
