# 학습 워커 설치 — 저장소용 메모

**절차의 정본은 「BODA VMS MLOps 설치 가이드」문서입니다.** 본문 `docs/manual/install.json` 의 4·5·9장에
토큰 발급 · MSI 마법사 · 무인 설치 · `configure` 옵션 · 첫 기동에 일어나는 일 · 폐쇄망 설치 · 문제 해결이 있습니다.
설계 근거는 `MLOps Phase3 학습 워커 설계 명세.md` §6·§10 입니다.

이 파일에는 고객에게 나가는 문서에 넣지 않는 것, 저장소 안에서만 쓰는 것만 남깁니다.

## 한 줄 요약

패키지 프로젝트 `src/BODA.VMS.MLOps.TrainWorker.Setup` (WiX 6, **솔루션 밖 — 따로 빌드**) ·
서비스 `BodaVmsTrainWorker` · 설정 `%ProgramData%\BODA VMS TrainWorker\worker.json` ·
패키지 허용 목록 `scripts/requirements-allowlist.txt`.

## 설치 패키지 만들기

```powershell
# 폐쇄망용일 때만 → src\BODA.VMS.MLOps.TrainWorker.Setup\WheelBundle\ (약 6GB)
.\scripts\make-wheel-bundle.ps1
dotnet build src\BODA.VMS.MLOps.TrainWorker.Setup -c Release
# → bin\Release\BODA-VMS-TrainWorker-<버전>[-offline].msi
```

번들이 있으면 산출물 이름에 `-offline` 이 붙고, 설치 때 `configure --wheels` 가 자동으로 들어갑니다.
`make-wheel-bundle.ps1` 은 마지막에 임시 venv 를 만들어 번들만으로 전체 설치가 되는지, 그리고
torch 가 CUDA 빌드(`+cu124`)인지 확인합니다.

MSI 문자열은 코드페이지 949 라 `—`·`▸`·`…` 를 속성값·대화상자 텍스트에 넣으면 WIX0311 로 막힙니다(주석은 괜찮습니다).
대화상자 텍스트의 `[…]` 는 속성 참조로 읽히므로 "[토큰 발급]" 같은 표기는 ICE03 입니다.

## 마법사 화면을 확인할 때

**워커가 이미 설치된 PC 에서는 "워커 연결 설정" 화면에 도달할 수 없습니다.** `WixUI_WorkerInstall.wxs` 에서
`WelcomeDlg` 의 [다음] 이 `NOT Installed` 조건이라, 설치된 상태로 MSI 를 실행하면 유지 관리 모드(복구·제거)로 빠집니다.

같은 PC 에서 그 화면을 봐야 한다면 **버전만 올려 MSI 를 따로 빌드**하세요. ProductCode 가 달라져
첫 설치 UI 가 그대로 나옵니다. 설정 화면까지 간 뒤 **[설치] 를 누르기 전에 취소**하면
"시스템이 수정되지 않았습니다" 로 끝나고 돌고 있는 워커는 그대로입니다.

```powershell
dotnet build src\BODA.VMS.MLOps.TrainWorker.Setup -c Release -p:Version=<다음 버전>
```

끝나면 그 MSI 를 지우고 `-t:Rebuild` 로 원래 버전을 다시 만들어 두세요 —
버전을 바꿔 빌드하면 `bin\Release` 의 이전 산출물이 사라집니다 (2026-09-21 실증).

## 패키지 허용 목록을 고칠 때

`scripts/requirements-allowlist.txt` 의 버전 범위는 **wheel 인덱스가 실제로 가진 것**이 정합니다.
파일 안 주석에 지금 상한이 왜 그 값인지 적어 두었습니다 (torch 는 cu124 인덱스의 Windows cp312 wheel 이
2.6.0 까지, transformers 는 rfdetr 이 5.1 이상을 요구). 범위를 넓히거나 좁히기 전에 그 주석부터 보세요.

바꿨다면 **빈 환경에 실제로 설치해 확인합니다.** 해결기는 조건을 만족하는 조합을 찾아내지만,
그 조합이 CPU 빌드일 수 있고 그러면 워커는 Disabled 로만 나타납니다.

```powershell
py -3.12 -m venv C:\temp\wheelcheck
C:\temp\wheelcheck\Scripts\pip install -r scripts\requirements-allowlist.txt
C:\temp\wheelcheck\Scripts\python scripts\worker_diag.py
```

JSON 한 줄이 나옵니다. `packages.torch` 가 `+cu124` 로 끝나고 `failures` 가 비어 있어야 합니다.
`worker_diag.py` 는 CPU 빌드를 `torch.version.cuda is None` 으로 잡아 `failures` 에 담는데,
워커는 이 목록이 비어 있어야 Online 으로 등록됩니다 — 하나라도 있으면 Disabled 로 서서 작업을 받지 않습니다.

## 실증 기록 (2026-09-10 · RTX 4060 Laptop 8GB · Windows 11 · Python 3.12.10)

온라인 venv 부트스트랩 결과 `torch 2.6.0+cu124` · `torchvision 0.21.0+cu124` · `transformers 5.17.0` ·
`rfdetr 1.10.1` · `anomalib 1.2.0`. 로컬 서버에 Detection 작업(D-FINE small, 2장·2 에폭)을 제출해
워커가 받아 학습 · ONNX 검증 · Candidate 등록까지 약 50초.

MSI 0.1.0 무인 설치(`SERVERURL`/`WORKERTOKEN`): 서비스 LocalSystem · 자동(지연) 등록, `worker.json` 생성, 즉시 시작.
이 PC 의 Python 3.12 는 **사용자 전용 설치**라 서비스가 PATH 의 3.14 를 잡아 torch 설치에 실패했습니다.
`configure --python` 으로 기존 venv 를 지정하니 세션 0(LocalSystem)에서도 CUDA 가 잡혀 Online 으로 등록됐고,
서비스로 도는 워커가 3 에폭 작업을 받아 Candidate 까지 등록했습니다(약 55초).
정본 문서의 "모든 사용자용으로 설치" 경고와 4.7 절이 여기서 나왔습니다.

그 뒤 같은 PC 에 **0.1.1.0 이 설치되어**(2026-09-14) 서비스로 돌고 있습니다. `Directory.Build.props` 의
`Version` 도 0.1.1 입니다 — 위 기록의 0.1.0 은 그때 값이고 지금 산출물 이름과는 다릅니다.
