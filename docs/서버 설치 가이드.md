# BODA VMS MLOps 서버 설치 가이드 (Windows 서비스)

문서 버전 v1.1 (2026-09-11) · 대상: 공장 안 관리 서버 PC(또는 올인원 GPU PC)에 MLOps 서버를 상시 가동하는 엔지니어 · 설치 패키지: `BODA-VMS-MLOps-Server-<버전>.msi`

MLOps 서버는 모델 레지스트리·데이터셋·라벨링·학습 작업 큐·모니터링을 한 프로세스(ASP.NET Core, SQLite)로 제공합니다.
라인 PC(NG 사진 올리기·모델 받기), 브라우저(관리 화면), 학습 워커가 모두 이 서버의 포트(기본 5310)로 붙습니다.

설치 방법은 둘입니다. **현장에는 설치 패키지(MSI)를 씁니다.** 저장소와 .NET SDK 가 필요 없고, 업그레이드 때 설정을 다시 묻지 않습니다.
스크립트(`scripts/install-server-service.ps1`)는 저장소가 있는 개발 PC 에서 publish 부터 한 번에 돌릴 때 씁니다 (§5).
**한 PC 에 둘을 함께 쓰지 않습니다** — 같은 서비스 이름을 쓰므로, 스크립트로 깐 서비스가 있으면 MSI 가 설치를 막고 먼저 지우라고 알려 줍니다.

## 1. 준비물

| 항목 | 요구 |
|---|---|
| OS | Windows 10/11 64-bit 또는 Windows Server 2019+ (관리자 권한) |
| 설치 패키지 | `BODA-VMS-MLOps-Server-<버전>.msi` (이름 끝에 `-sam` 이 붙으면 SAM 보조 라벨링 모델이 들어 있다) |
| 디스크 | 이미지·데이터셋·모델이 쌓이는 데이터 폴더를 큰 드라이브에 (라인 NG 사진은 원본 해상도로 들어온다) |
| 운영 웹 | **로그인 토큰을 발급할 BODA.VMS.Web 인스턴스**의 `Jwt:Key` (32자 이상). 운영 웹과 개발 웹은 키가 다르다. Issuer `BODA.VMS.Web`·Audience `BODA.VMS.Web.Client` 는 설치가 맞춰 둔다 |
| 네트워크 | 포트 5310/TCP 인바운드 (설치가 방화벽 예외를 만든다) |

.NET 런타임은 필요 없습니다 (자체 포함 빌드).

## 2. 설치 (MSI)

MSI 를 두 번 눌러 실행합니다. 설치 폴더를 고른 뒤 **서버 설정** 화면이 나옵니다.

| 항목 | 기본 | 뜻 |
|---|---|---|
| 데이터 폴더 | `C:\ProgramData\BODA VMS MLOps` | `mlops.db` · `storage\` · `logs\` — **백업 대상**. 큰 드라이브를 고르세요 (예: `D:\BODA-MLOps`) |
| 포트 | 5310 | 서비스 포트. 방화벽 예외가 이 포트로 만들어진다 |
| 운영 웹 내부 주소 | `http://localhost:5292` | 모니터링용. 비우면 모니터링만 꺼진다. **Cloudflare 터널 주소는 쓰지 않는다** |
| Jwt 키 | (비어 있음) | 운영 웹과 같은 키. 이 PC 에서만 풀리게 암호화해 관리자만 읽을 수 있는 파일에 둔다 |

끝나면 서비스 `BodaVmsMlops`(자동·지연 시작, 실패 시 재시작, LocalSystem)가 시작됩니다.
`http://<서버>:5310` 이 관리 화면이고 `/health` 가 설치된 버전을 알려 줍니다. 로그인은 운영 웹에서 받은 토큰을 붙여 넣습니다(개발용 역할 버튼은 꺼져 있습니다).

**Jwt 키를 비워 두고 설치하면** 파일만 놓이고 서비스는 멈춘 채로 남습니다. 나중에 관리자 명령 프롬프트에서:

```bat
"C:\Program Files\BODA Vision AI\BODA VMS MLOps Server\BODA.VMS.MLOps.Server.exe" configure --jwt-key <키>
sc start BodaVmsMlops
```

### 무인 설치

```bat
msiexec /i BODA-VMS-MLOps-Server-0.1.1-sam.msi /qn JWTKEY=<키> DATADIR=D:\BODA-MLOps PORT=5310 WEBURL=http://localhost:5292 /l*v install.log
```

`JWTKEY` 는 로그에 찍히지 않도록 숨긴 속성입니다. 그래도 설치 로그를 밖으로 내보냈다면 키 교체를 검토하세요 —
이 키로 MLOps 와 운영 웹 **양쪽의** 관리자 토큰을 만들 수 있습니다.

### 설치가 놓는 것

| 자리 | 내용 | 제거하면 |
|---|---|---|
| `C:\Program Files\BODA Vision AI\BODA VMS MLOps Server\` | 서버 · 관리 화면(wwwroot) · 워커에 나눠 줄 scripts · (선택) models\sam | 지워진다 |
| `C:\ProgramData\BODA VMS MLOps\server.json` | 설정 (Jwt 키는 DPAPI 로 감싸고 파일 권한을 SYSTEM·관리자로 좁힌다) | **남는다** |
| 데이터 폴더 | `mlops.db` · `storage\` · `logs\` | **남는다** |
| 서비스 `BodaVmsMlops`, 방화벽 예외 "BODA VMS MLOps Server" | | 지워진다 |

설정과 데이터를 남기는 것은 일부러입니다 — 다시 설치하면 그대로 이어서 뜹니다. 재설치가 곧 복구입니다.

## 3. 설치 뒤 1회 준비

1. **관리자 계정으로 로그인** (운영 웹 Admin 토큰).
2. **워커 등록**: 워커 ▸ [워커 추가] → 토큰 복사 → GPU PC 에 워커 MSI 설치 (`워커 설치 가이드.md`). 올인원이면 같은 PC 에 `http://localhost:5310` 으로.
3. **사전학습 미러**: 사전학습 ▸ [추가] 로 백본 가중치 등록 (예: `dfine-small-obj2coco` 의 `config.json` + `model.safetensors`). 워커는 인터넷에서 가중치를 받지 않으므로 이것이 없으면 학습이 실패합니다.
4. **라인 PC**: 관리 화면에서 라인 등록·라인 토큰 발급 → 각 라인 PC 의 VMS 설정 마법사(AppSetup) 고급 설정에 MLOps 서버 주소·라인 토큰 입력, 이미지 저장 설정의 [NG 이미지 MLOps 전송] 체크.
   **라인 PC 가 다른 PC 면 주소를 `https://` 로** 주세요 — VMS 는 운영 보안 모드에서 같은 PC(localhost)가 아닌 `http://` 를 막습니다.
5. **백업**: 데이터 폴더 전체와 `C:\ProgramData\BODA VMS MLOps\server.json`. 서비스를 멈추지 않고 복사해도 되지만(SQLite WAL) 정합성을 원하면 야간에 서비스를 잠깐 멈추고 복사합니다.
   `server.json` 의 키는 **이 PC 에서만 풀립니다** — 다른 PC 로 옮겨 복구할 때는 그 PC 에서 `configure --jwt-key` 로 키를 다시 넣습니다.

## 4. 갱신 · 제거 · 문제 해결

- **갱신**: 새 MSI 를 실행합니다. 데이터 폴더·포트·운영 웹 주소는 지난 값으로 채워져 있고 **Jwt 키는 비워 두면 있던 것을 씁니다.** 스키마 변경은 부팅 때 마이그레이션으로 적용됩니다.
- **설정 바꾸기**: MSI 를 다시 돌리거나, 관리자 명령 프롬프트에서 `BODA.VMS.MLOps.Server.exe configure` 에 바꿀 것만 줍니다 (`--port 5320`, `--web-url ...`, `--data-dir ...`, `--jwt-key ...`). 주지 않은 값은 그대로입니다. 끝나면 서비스를 다시 시작합니다.
- **제거**: 설정 ▸ 앱에서 "BODA VMS MLOps Server". 데이터 폴더와 `server.json` 은 남습니다.
- **로그**: `<데이터 폴더>\logs\server-yyyyMMdd.log` (30일 보존). 서비스가 바로 멈추면 이 파일의 첫 오류를 봅니다.
  - `server.json 의 Jwt 키를 풀지 못했습니다` — 다른 PC 에서 옮겨 온 설정 파일입니다. 이 PC 에서 `configure --jwt-key` 로 다시 넣으세요.
  - `Jwt:Key 가 설정되지 않았거나 32자 미만` — 키 없이 설치했습니다. 위 §2 의 `configure` 를 실행하세요.
  - 데이터 폴더 권한 — 서비스는 LocalSystem 으로 돕니다. 네트워크 드라이브는 쓰지 마세요.
- **설치가 "스크립트로 설치한 서비스가 있습니다" 로 멈춤**: 관리자 PowerShell 에서 저장소의 `scripts\install-server-service.ps1 -Uninstall` 로 지운 뒤 다시 설치합니다. 데이터 폴더는 지워지지 않으니, 설치 화면에서 **그 데이터 폴더를 그대로 고르면** 이어서 씁니다.
- **포트 충돌**: `netstat -ano | findstr :5310`. 개발 중 `dotnet run` 을 같은 포트로 띄우면 서비스와 충돌합니다.
- **로그인 "서버가 토큰을 거부했습니다"**: 붙여 넣은 토큰을 발급한 Web 의 `Jwt:Key` 와 서버의 키가 다릅니다. 어느 Web 인지는 `tasklist /svc /fi "PID eq <netstat 의 5292 PID>"` 로 확인한다 — 개발 PC 에서도 5292 를 서비스(`BODA-VMS-Web`)가 듣고 있을 수 있고, 그 키는 개발 프로젝트 user-secrets 키와 다르다 (2026-09-10 실증). 어느 Web(운영/개발)에서 로그인했는지 확인하고 그 키로 `configure --jwt-key` 를 다시 줍니다. (audience 불일치도 같은 증상)
- **모니터링 "볼 수 없음"**: 운영 웹 주소가 비었거나 운영 웹이 401 을 냅니다(키 불일치). 다른 기능은 그대로 돕니다.
- **개발 PC 겸용 주의**: 서비스는 설치 폴더의 사본으로 돌므로 저장소를 빌드해도 잠기지 않습니다. 대신 개발 서버를 띄울 때는 포트를 바꾸거나 서비스를 잠시 멈춥니다. `dotnet run`(개발 환경)은 `server.json` 을 읽지 않으므로 개발 서버가 운영 DB 를 집어 가는 일은 없습니다.

## 5. 스크립트로 설치 (저장소가 있는 개발 PC)

MSI 없이 저장소에서 바로 publish 해서 서비스로 올립니다. 관리자 PowerShell 에서:

```powershell
cd D:\Repo\BODA.VMS.MLOps
.\scripts\install-server-service.ps1 -DataDir D:\BODA-MLOps -ProductionWebUrl http://<운영 웹 내부 주소>:5292
```

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `-InstallDir` | `C:\Program Files\BODA Vision AI\BODA VMS MLOps Server` | 프로그램 파일 |
| `-DataDir` | `C:\ProgramData\BODA VMS MLOps` | `mlops.db` · `storage\` · `logs\` — **백업 대상** |
| `-Port` | 5310 | 서비스 포트 (0.0.0.0 바인딩) |
| `-ProductionWebUrl` | `http://localhost:5292` | 운영 웹 내부 주소 (모니터링용) |
| `-JwtKey` | (환경변수 `MLOPS_JWT_KEY` → 서버 프로젝트 user-secrets) | 운영 웹과 같은 키. 파일에 남기지 않고 서비스 환경변수 `Jwt__Key` 로 준다 |
| `-SkipPublish` / `-PublishDir` | | 이미 publish 한 산출물을 쓸 때 |
| `-Uninstall` | | 서비스·방화벽 규칙만 제거 (파일·데이터는 남김) |

스크립트는 설정을 설치 폴더의 `appsettings.Production.json` 에 씁니다. 같은 PC 에 지난 MSI 설치가 남긴 `server.json` 이 있어도
**스크립트의 설정이 이깁니다** (우선순위: appsettings.json < server.json < appsettings.Production.json < 환경변수 < 명령줄).
갱신은 같은 명령을 다시 실행합니다.

## 부록 A. 설치 패키지 만들기 (개발자)

```powershell
dotnet build src\BODA.VMS.MLOps.Server.Setup -c Release
# → src\BODA.VMS.MLOps.Server.Setup\bin\Release\BODA-VMS-MLOps-Server-<버전>[-sam].msi
```

버전은 `Directory.Build.props` 의 `Version` 입니다. 빌드마다 서버를 자체 포함으로 다시 publish 합니다(수 분).
`src\BODA.VMS.MLOps.Server\models\sam` 에 SAM 모델 파일이 있으면 함께 싣고 이름에 `-sam` 이 붙습니다(0.1.1 기준 154MB). 없으면 SAM 보조 라벨링만 꺼진 패키지가 됩니다.
솔루션(slnx)에는 넣지 않았습니다 — 매 빌드마다 publish 가 도는 것을 피하기 위해서입니다.
**개발용 `appsettings.Development.json`(개발 Jwt 키가 들어 있다)은 패키지에서 뺍니다** — Package.wxs 의 Exclude 를 지우지 마세요.

## 부록 B. 이 PC 에서 확인된 값 (2026-09-10)

dev PC(RTX 4060): publish 174MB(389 파일, scripts·wwwroot 포함). 데이터 폴더 `D:\BODA-MLOps`, 운영 웹은 같은 PC 의 5292.
관리자 JWT 는 같은 `Jwt:Key` 로 HS256 발급(`sub`·`unique_name`·`role` 클레임, iss/aud `BODA.VMS.Web`)하면 통한다 — 운영 웹 없이 첫 로그인을 만들 때 쓴 방법.
