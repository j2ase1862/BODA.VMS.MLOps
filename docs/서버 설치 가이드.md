# MLOps 서버 설치 — 저장소용 메모

**절차의 정본은 「BODA VMS MLOps 설치 가이드」문서입니다.** 본문은 `docs/manual/install.json`,
만드는 법은 `docs/manual/README.md` 에 있습니다. 준비물 · 설치 명령 · 옵션 표 · 설치 확인 ·
백업/갱신/제거 · 문제 해결이 모두 거기 있습니다. **스크립트를 고치면 그 json 을 함께 고치세요.**

이 파일에는 고객에게 나가는 문서에 넣지 않는 것, 저장소 안에서만 쓰는 것만 남깁니다.

## 한 줄 요약

스크립트 `scripts/install-server-service.ps1` · 서비스 `BodaVmsMlops` · 기본 포트 5310 ·
백업 대상은 `-DataDir` 폴더 하나.

```powershell
.\scripts\install-server-service.ps1 -DataDir D:\BODA-MLOps -ProductionWebUrl http://<운영 웹>:5292
```

옵션 전체는 정본 3.2 절, 또는 스크립트의 `param(...)` 블록을 보세요.

## 개발 PC 를 겸할 때

- 서비스는 설치 폴더의 **사본**으로 돌기 때문에 저장소를 빌드해도 실행 파일이 잠기지 않습니다.
  대신 개발 서버를 `dotnet run` 으로 띄울 때 5310 이 겹치므로, 포트를 바꾸거나 서비스를 잠시 멈춥니다.
- SAM 모델 파일은 저장소에 없습니다. `src/BODA.VMS.MLOps.Server/models/sam` 에 두면 설치 스크립트가 함께 복사합니다.
  설치 폴더의 `models\` 와 `appsettings.Production.json` 은 재설치해도 보존됩니다.

## 운영 웹이 없는 설치

`-Local` 을 붙이면 이 서버가 계정을 직접 관리합니다 (정본 3.5 절). 서명 키는 스크립트가 만들어
서비스 환경변수 `Auth__Local__Key` 에 넣고, 첫 관리자와 임시 비밀번호는 서버가 만들어
설치 폴더의 `initial-admin-password.txt` 에 한 번 남깁니다 — 스크립트가 그 내용을 화면에도 찍습니다.

```powershell
.\scripts\install-server-service.ps1 -Local -DataDir D:\BODA-MLOps
```

재설치해도 그 키는 유지됩니다(레지스트리의 기존 값을 읽어 씁니다). 키를 바꾸면 그 순간 모두 다시 로그인해야 합니다.

## 다른 PC 에서 https 로 쓰기

라인 PC(VMS)가 **다른 PC** 에서 이 서버에 붙는 현장에서 필요합니다. VMS 는 보안 모드가 Production(기본값)이면
다른 PC 의 `http://` 서버 주소를 거부합니다(같은 PC 의 `http://localhost` 는 허용). 그래서 서버가 https 포트를 열고,
접속하는 PC 가 그 인증서를 신뢰해야 합니다. 옵션을 주지 않은 설치는 종전과 같습니다(http 5310 만).

> 이 절은 아직 정본(`docs/manual/install.json`)에 없습니다. 정본에 옮길 때 이 절을 그대로 쓰면 됩니다.

### 1. 인증서 준비 (서버 PC, 관리자 PowerShell)

인증서는 서버 PC 의 인증서 저장소 **로컬 컴퓨터 ▸ 개인**(`Cert:\LocalMachine\My`)에 있어야 하고, 설치 스크립트에는
그 **지문**(thumbprint)을 줍니다. `.pfx` 파일을 직접 읽지 않는 이유는 그 비밀번호를 설정 파일이나 서비스 환경변수에
남기지 않기 위해서입니다.

사내망 전용(공인 인증서 없음)이면 보조 스크립트로 만듭니다.

```powershell
.\scripts\new-https-certificate.ps1
```

자체 서명 인증서를 저장소에 넣고, 화면에 **지문**을 보여 주고, 현재 폴더에 공개 인증서
`boda-vms-https-<PC 이름>.cer`(개인 키 없음)를 내보냅니다. 인증서에는 이 PC 의 이름 · IPv4 주소 · `localhost` 가
들어갑니다. 다른 이름이나 주소로 접속할 계획이면 `-DnsName` · `-IpAddress` 로 더 넣습니다.
운영 웹과 같은 PC 라면 **인증서 하나를 두 서버가 같이 씁니다** — 한 번만 만드세요
(BODA.VMS.Web 의 `deploy\New-HttpsCertificate.ps1` 과 같은 스크립트입니다).

받은 인증서(.pfx)가 있으면 저장소에 넣고 지문을 확인합니다.

```powershell
Import-PfxCertificate -FilePath D:\server.pfx -CertStoreLocation Cert:\LocalMachine\My `
    -Password (Read-Host -AsSecureString "pfx 비밀번호")
Get-ChildItem Cert:\LocalMachine\My | Format-List Subject, NotAfter, Thumbprint
```

### 2. 서버 설치 (서버 PC, 관리자 PowerShell)

```powershell
.\scripts\install-server-service.ps1 -DataDir D:\BODA-MLOps `
    -ProductionWebUrl https://<운영 웹 이름>:5293 -HttpsCertThumbprint <지문>
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-HttpsCertThumbprint` | (없음) | 주면 https 를 엽니다. `Cert:\LocalMachine\My` 에 있는 서버 인증서의 지문 |
| `-HttpsPort` | 5311 | https 포트. `-HttpsCertThumbprint` 를 줄 때만 쓰입니다 |

이렇게 설치하면:

| 포트 | 받는 곳 | 방화벽 |
|---|---|---|
| 5311 (https) | 모든 네트워크 인터페이스 | `BODA VMS MLOps (5311/TCP)` 인바운드 허용 |
| 5310 (http) | 이 PC 안에서만 (`localhost`) | 규칙을 지웁니다 |

- **http 5310 은 다른 PC 에서 더 이상 닿지 않습니다.** 다른 PC 의 브라우저 · 라인 PC · 학습 워커는 모두
  `https://<서버 이름>:5311` 로 바꿔야 합니다. 같은 PC 의 워커(`http://localhost:5310`)와 설치 스크립트의
  응답 확인은 그대로입니다.
- 스크립트가 하는 일은 두 가지뿐입니다 — `appsettings.Production.json` 의 `Urls` 를
  `http://localhost:5310;https://0.0.0.0:5311` 로 쓰고, 서비스 환경변수 `Kestrel__Certificates__Default__*` 로
  저장소의 인증서를 가리킵니다. 서버 프로그램은 바뀌지 않습니다.
- 설치 전에 인증서를 확인합니다(저장소에 있는지 · 개인 키 · 유효 기간 · 서버 인증 용도 · 같은 이름의 다른 인증서).
  문제가 있으면 무엇도 바꾸기 전에 멈춥니다.
- https 를 끄려면 옵션 없이 다시 설치합니다. https 방화벽 규칙은 그때 지워지고 5310 규칙이 다시 생깁니다.

**운영 웹 모드(`-Local` 이 아닐 때)는 운영 웹도 https 여야 합니다.** 로그인 화면은 아이디 · 비밀번호를
브라우저가 운영 웹으로 곧장 보내는데, https 화면에서 `http://` 주소로 보내는 요청은 브라우저가 막습니다.
그래서 `-ProductionWebUrl` 을 운영 웹의 https 주소로 줍니다. 그 주소는 이 서버도 부르므로(모니터링 · 토큰 확인)
**이 서버 PC 가 운영 웹의 인증서를 신뢰해야 하고, 주소의 이름이 인증서에 들어 있어야 합니다** — 자체 서명
인증서라면 이 PC 에서도 3 단계를 하거나, 같은 PC 라면 인증서를 만들 때 `-TrustOnThisPc` 를 붙입니다.
그리고 운영 웹의 `Cors:AllowedOrigins` 에 넣는 주소도 https 주소(`https://<MLOps 서버 이름>:5311`)로 바뀝니다 —
설치가 끝나면 스크립트가 후보를 보여 줍니다.

### 3. 접속하는 PC 가 인증서를 믿게 하기 (라인 PC · 다른 PC 의 워커, 관리자)

공인 인증서나 사내 인증 기관(이미 PC 들이 믿는)의 인증서라면 필요 없습니다. 보조 스크립트로 만든 인증서는
접속하는 PC 마다 공개 인증서(`.cer`)를 한 번 넣습니다.

```powershell
certutil -addstore -f Root D:\boda-vms-https-SERVER01.cer
```

**로컬 컴퓨터 ▸ 신뢰할 수 있는 루트 인증 기관**에 들어가며 VMS · 학습 워커 · 브라우저(Edge · Chrome)가 모두 이 목록을 씁니다.
인증서 검증을 끄는 설정은 쓰지 않습니다.

### 4. 주소 넣기 · 확인

1. 접속하는 PC 의 브라우저로 `https://<서버 이름>:5311` 을 엽니다. 경고 없이 로그인 화면이 나와야 합니다.
2. 라인 PC: VMS 설정 마법사(AppSetup) 2단계 고급 설정의 MLOps 서버 주소에 `https://<서버 이름>:5311` 을 넣습니다.
3. 다른 PC 의 워커: `SERVERURL=https://<서버 이름>:5311` 로 설치하거나
   `BODA.VMS.MLOps.TrainWorker.exe configure --server https://<서버 이름>:5311 --token wk_…` 로 다시 설정합니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 브라우저 경고(인증 기관을 신뢰할 수 없음) | 그 PC 가 인증서를 믿지 않습니다 | 3 단계를 그 PC 에서 합니다 |
| 브라우저 경고(이름이 맞지 않음) | 주소에 쓴 이름/IP 가 인증서에 없습니다 | 인증서에 든 이름으로 접속하거나 `-DnsName` · `-IpAddress` 로 다시 만듭니다 |
| https 화면은 뜨는데 로그인만 안 됩니다 | 운영 웹 주소가 http 이거나, 운영 웹 CORS 에 https 주소가 없습니다 | 위 "운영 웹 모드" 문단 |
| 다른 PC 의 워커가 Offline | 워커가 아직 `http://<서버>:5310` 을 봅니다 | 4-3 |
| 서비스가 뜨지 않습니다 | 인증서를 저장소에서 지웠거나 5311 을 다른 프로그램이 씁니다 | `<DataDir>\logs\server-<날짜>.log` 의 첫 오류. 옵션 없이 다시 설치하면 http 로 돌아갑니다 |
| 어느 날부터 모두 붙지 못합니다 | 인증서 만료 | 새로 만들어 서버를 다시 설치하고 새 `.cer` 를 PC 마다 넣습니다 |

만료일은 설치 완료 화면에 나옵니다(보조 스크립트 기본 5년). 서버 IP 가 DHCP 로 바뀌면 그 IP 로는 접속되지 않으니
고정 IP 를 쓰거나 PC 이름으로 접속합니다.

## 어느 Web 의 키인지 확인하기

로그인이 "서버가 토큰을 거부했습니다" 로 막히면, 토큰을 발급한 Web 의 `Jwt:Key` 와 서비스의 `Jwt__Key` 가 다른 것입니다.
**개발 PC 에서도 5292 를 설치본 서비스(`BODA-VMS-Web`)가 듣고 있을 수 있고, 그 키는 개발 프로젝트
user-secrets 의 키와 다릅니다** (2026-09-10 실증). 어느 쪽에 로그인했는지부터 확인하세요.

```powershell
netstat -ano | findstr :5292
tasklist /svc /fi "PID eq <위에서 본 PID>"
```

audience 불일치도 증상이 같습니다 — 템플릿 기본값 `BODA.VMS.Web.Client` 를 바꾸지 않았는지 보세요.
