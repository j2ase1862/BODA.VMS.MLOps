# MLOps 서버 설치 — 저장소용 메모

**절차의 정본은 「BODA VMS MLOps 설치 가이드」문서입니다.** 본문은 `docs/manual/install.json`,
만드는 법은 `docs/manual/README.md` 에 있습니다. 준비물 · 설치 명령 · 옵션 표 · 설치 확인 ·
백업/갱신/제거 · 문제 해결이 모두 거기 있습니다. **스크립트를 고치면 그 json 을 함께 고치세요.**

이 파일에는 고객에게 나가는 문서에 넣지 않는 것, 저장소 안에서만 쓰는 것만 남깁니다.

## 한 줄 요약

스크립트 `scripts/install-server-service.ps1` · 서비스 `BodaVmsMlops` · 기본 포트 5310 ·
백업 대상은 `-DataDir` 폴더 하나.

```powershell
.\scripts\install-server-service.ps1 -DataDir D:\BODA-MLOps -ProductionWebUrl http://<운영 웹>:5292
```

옵션 전체는 정본 3.2 절, 또는 스크립트의 `param(...)` 블록을 보세요.

## 개발 PC 를 겸할 때

- 서비스는 설치 폴더의 **사본**으로 돌기 때문에 저장소를 빌드해도 실행 파일이 잠기지 않습니다.
  대신 개발 서버를 `dotnet run` 으로 띄울 때 5310 이 겹치므로, 포트를 바꾸거나 서비스를 잠시 멈춥니다.
- SAM 모델 파일은 저장소에 없습니다. `src/BODA.VMS.MLOps.Server/models/sam` 에 두면 설치 스크립트가 함께 복사합니다.
  설치 폴더의 `models\` 와 `appsettings.Production.json` 은 재설치해도 보존됩니다.

## 어느 Web 의 키인지 확인하기

로그인이 "서버가 토큰을 거부했습니다" 로 막히면, 토큰을 발급한 Web 의 `Jwt:Key` 와 서비스의 `Jwt__Key` 가 다른 것입니다.
**개발 PC 에서도 5292 를 설치본 서비스(`BODA-VMS-Web`)가 듣고 있을 수 있고, 그 키는 개발 프로젝트
user-secrets 의 키와 다릅니다** (2026-09-10 실증). 어느 쪽에 로그인했는지부터 확인하세요.

```powershell
netstat -ano | findstr :5292
tasklist /svc /fi "PID eq <위에서 본 PID>"
```

audience 불일치도 증상이 같습니다 — 템플릿 기본값 `BODA.VMS.Web.Client` 를 바꾸지 않았는지 보세요.

## 운영 웹 없이 첫 로그인 만들기

운영 웹이 없는 PC 에서 관리 화면을 열어야 할 때는, 같은 `Jwt:Key` 로 HS256 토큰을 직접 발급해
붙여 넣으면 통합니다. 클레임은 `sub`·`unique_name`·`role`, iss/aud 는 서버의 `Jwt:Issuer`·`Jwt:Audience` 와 같게.
시험용이며 운영에서는 쓰지 않습니다.
