# BODA VMS MLOps 서버 설치 가이드 (Windows 서비스)

문서 버전 v1.0 (2026-09-10) · 대상: 공장 안 관리 서버 PC(또는 올인원 GPU PC)에 MLOps 서버를 상시 가동하는 엔지니어 · 스크립트: `scripts/install-server-service.ps1`

MLOps 서버는 모델 레지스트리·데이터셋·라벨링·학습 작업 큐·모니터링을 한 프로세스(ASP.NET Core, SQLite)로 제공합니다.
라인 PC(NG 사진 올리기·모델 받기), 브라우저(관리 화면), 학습 워커가 모두 이 서버의 포트(기본 5310)로 붙습니다.

## 1. 준비물

| 항목 | 요구 |
|---|---|
| OS | Windows 10/11 64-bit 또는 Windows Server 2019+ (관리자 권한) |
| 빌드 PC | .NET SDK 8+ 와 이 저장소 (publish 는 빌드 PC 에서, 설치는 산출물 폴더만 옮겨도 됨) |
| 디스크 | 이미지·데이터셋·모델이 쌓이는 데이터 폴더를 큰 드라이브에 (라인 NG 사진은 원본 해상도로 들어온다) |
| 운영 웹 | BODA.VMS.Web 의 `Jwt:Key` (같은 키여야 웹 로그인 토큰이 여기서도 통한다) |
| 네트워크 | 포트 5310/TCP 인바운드 (스크립트가 방화벽 규칙을 만든다) |
| SAM 모델 | `models/sam` 4개 파일 (없으면 SAM 보조 라벨링만 꺼진 채 뜬다) |

## 2. 설치

관리자 PowerShell 에서:

```powershell
cd D:\Repo\BODA.VMS.MLOps
.\scripts\install-server-service.ps1 -DataDir D:\BODA-MLOps -ProductionWebUrl http://<운영 웹 내부 주소>:5292
```

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `-InstallDir` | `C:\Program Files\BODA Vision AI\BODA VMS MLOps Server` | 프로그램 파일 |
| `-DataDir` | `C:\ProgramData\BODA VMS MLOps` | `mlops.db` · `storage\` · `logs\` — **백업 대상** |
| `-Port` | 5310 | 서비스 포트 (0.0.0.0 바인딩) |
| `-ProductionWebUrl` | `http://localhost:5292` | 운영 웹 내부 주소 (모니터링용). Cloudflare 터널 주소는 쓰지 않는다 |
| `-JwtKey` | (환경변수 `MLOPS_JWT_KEY` → 서버 프로젝트 user-secrets) | 운영 웹과 같은 키. 파일에 남기지 않고 서비스 환경변수 `Jwt__Key` 로 준다 |
| `-SkipPublish` / `-PublishDir` | | 이미 publish 한 산출물을 쓸 때 |
| `-Uninstall` | | 서비스·방화벽 규칙만 제거 (파일·데이터는 남김) |

스크립트가 하는 일: self-contained win-x64 publish → 설치 폴더 복사(기존 `appsettings.Production.json` 과 `models\` 보존) →
`appsettings.Production.template.json` 을 채워 `appsettings.Production.json` 생성 → 서비스 `BodaVmsMlops`(자동·지연 시작, 실패 시 재시작, LocalSystem) 등록 →
서비스 환경변수(`DOTNET_ENVIRONMENT=Production`, `Jwt__Key`) → 방화벽 인바운드 규칙 → SAM 모델 복사 → 시작 후 응답 확인.

끝나면 `http://<서버>:5310` 이 관리 화면이고 `/swagger` 가 API 문서입니다. 로그인은 운영 웹에서 받은 토큰을 붙여 넣습니다(개발용 역할 버튼은 꺼져 있습니다).

## 3. 설치 뒤 1회 준비

1. **관리자 계정으로 로그인** (운영 웹 Admin 토큰).
2. **워커 등록**: 워커 ▸ [워커 추가] → 토큰 복사 → GPU PC 에 워커 MSI 설치 (`워커 설치 가이드.md`). 올인원이면 같은 PC 에 `http://localhost:5310` 으로.
3. **사전학습 미러**: 사전학습 ▸ [추가] 로 백본 가중치 등록 (예: `dfine-small-obj2coco` 의 `config.json` + `model.safetensors`). 워커는 인터넷에서 가중치를 받지 않으므로 이것이 없으면 학습이 실패합니다.
4. **라인 PC**: 관리 화면에서 라인 등록·라인 토큰 발급 → 각 라인 PC 의 VMS 설정 마법사(AppSetup) 고급 설정에 MLOps 서버 주소·라인 토큰 입력, 이미지 저장 설정의 [NG 이미지 MLOps 전송] 체크.
5. **백업**: `-DataDir` 폴더 전체. 서비스를 멈추지 않고 복사해도 되지만(SQLite WAL) 정합성을 원하면 야간에 서비스를 잠깐 멈추고 복사합니다.

## 4. 갱신 · 제거 · 문제 해결

- **갱신**: 새 코드로 같은 명령을 다시 실행합니다. 설정과 데이터는 그대로 두고 파일만 바꾼 뒤 서비스를 다시 시작합니다. 스키마 변경은 부팅 때 마이그레이션으로 적용됩니다.
- **제거**: `-Uninstall`. 데이터 폴더는 남습니다.
- **로그**: `<DataDir>\logs\server-yyyyMMdd.log` (30일 보존). 서비스가 바로 멈추면 이 파일의 첫 오류를 봅니다. 대개 `Jwt:Key` 32자 미만(부팅 거부) 또는 데이터 폴더 권한입니다.
- **포트 충돌**: `netstat -ano | findstr :5310`. 개발 중 `dotnet run` 을 같은 포트로 띄우면 서비스와 충돌합니다.
- **모니터링 "볼 수 없음"**: `ProductionWebUrl` 이 비었거나 운영 웹이 401 을 냅니다(키 불일치). 다른 기능은 그대로 돕니다.
- **개발 PC 겸용 주의**: 서비스는 설치 폴더의 사본으로 돌므로 저장소를 빌드해도 잠기지 않습니다. 대신 개발 서버를 띄울 때는 포트를 바꾸거나 서비스를 잠시 멈춥니다.
