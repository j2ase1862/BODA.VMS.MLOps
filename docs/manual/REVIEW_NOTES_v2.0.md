# 사용자 매뉴얼 v2.0 — 검토 메모 (2026-11-11)

v2.0 을 쓰면서 화면 코드와 대조하다 찾은 것입니다. 매뉴얼은 **지금 동작 그대로** 썼고, 화면이 기대와 다르게 동작하는 곳은 본문에 주의 · 알림으로 사실만 적었습니다. 고칠지는 따로 정합니다.

## A. 제품 쪽 동작 — 고칠 목록에 넣을지 결정 필요

> **2026-11-16 — A-1 ~ A-28 모두 처리됨(MLOps PR #67 — main 에 머지됨 458636e) · 본문을 고친 뒤 동작으로 다시 씀.**
> - A-1 은 결정(현행 유지): 라인은 레시피의 `model://` 참조를 따르고 [레시피 바인딩] 은 기록 — 화면 문구 · 13.5.1 을 그렇게 맞춤.
>   같은 날 VMS 도 레시피를 불러올 때 `model://` 모델을 받아 두게 고쳐(VMS PR #620, VM-40) 14.2 를 다시 씀.
> - A-2 운영 웹 레시피 드롭다운(도구 ID 는 연결한 적 있는 것만 제안), A-3 ~ A-28 은 ML-03 ~ ML-28 그대로.
> - A-20 은 안내만 고침(seed 를 실제로 받는 스크립트는 여전히 D-FINE · RF-DETR), A-22 는 스크립트 수정 — 실제 학습으로는 미확인.
> - 그림 재캡처 필요: 09 · 11 · 12 · 23 · 25 · 27 · 31 · 02 · 05, 그리고 Admin 으로 찍은 전체 화면(왼쪽 메뉴에 [감사 로그] 추가).

**배포 경로 (가장 큼)**
1. **[레시피 바인딩] 화면의 기록이 라인에 전달되지 않음.**
   - VMS(ModelReferenceResolver · ModelRegistryClient)는 레시피에 저장된 `model://` 참조로 `/resolve` 만 부르고, `/api/recipes/{id}/model-bindings/payload` 는 부르지 않습니다.
   - 그런데 화면의 성공 문구는 "다음 레시피 동기화 때 라인에 반영됩니다" 이고, [롤백] 도 라인에 아무 영향이 없습니다.
   - 매뉴얼은 VisionSetup [레지스트리…] 를 주 경로로 쓰고, 이 화면에는 주의를 달았습니다 (13.5).
2. 바인딩 화면에서 레시피 ID · 도구 ID 를 찾아 주는 기능이 없음 — GUID 를 직접 붙여 넣어야 함.

**라벨링**
3. 위쪽 [이전] · [다음] 버튼은 저장하지 않은 편집을 경고 없이 버림. ← / → 키만 저장한 뒤 넘어감 (Labeling.razor).
4. 분류 · 이상탐지에서 숫자키가 클래스를 강조만 하고 라벨을 붙이지 않음. 안내 줄은 "숫자키로 다음 클래스 · 끌어서 그리기" 그대로.
5. 잠금 끝 시각이 UTC 로 표시됨("… 작업 중입니다 (HH:mm 까지)"). 기본 판 이름의 시각도 UTC.
6. 잠금이 저장할 때만 연장됨(하트비트 없음, 10분). 오래 보고 있으면 다른 사람이 가져가고 내 저장이 거절됨.
7. OCR [텍스트 입력] 에서 [취소] 하면 글자 없는 상자가 남아 저장 · 화살표 이동이 막힘.
8. [반려] 는 검토 완료에서만 켜짐 — 라벨 완료 사진을 돌려보낼 수 없음.
9. 고른 범위 없이 [저장하고 다음] 을 쓰면 격자 순서가 아니라 애매함 · ID 순으로 이동.

**데이터셋 · 사진**
10. [데이터셋에서 빼기] 와 [자동 분할 8:2] 에 확인 창이 없음 (라벨 · 직접 정한 분할이 사라짐).
11. ROI "너무 작음" 경고가 가로 **그리고** 세로 모두 64 미만일 때만 뜸 (30×500 은 경고 없음).
12. 올리기의 "비슷한 사진" 알림이 화면에 나오지 않음 (서버는 dHash 로 계산만 함). v1.5 매뉴얼 문구를 지움.
13. 64MB 넘는 파일이 섞이면 올리기 반복이 중간에 멈추는 것으로 보임 (클라이언트 스트림 한도) — 시험 필요.
14. [데이터셋에 담기] 창에 작업 유형이 영어(Detection)로 나옴.
15. 목록 머리말 "작업 유형과 클래스는 만든 뒤에 바꿀 수 없습니다" — 클래스는 덧붙이기가 됨.
16. [모델로 미리 채우기] 버튼이 모든 작업 유형에 보이지만 서버는 검출만 받음. 빈 목록 문구도 "검출 모델" 고정.
17. 태그 필터의 개수는 부분 일치, 목록은 전체 일치로 세어 "N 장" 과 보이는 장수가 다를 수 있음.
18. 같은 문턱을 미리 채우기는 "확신도", 새 사진 훑기 · 돌려 보기는 "신뢰도" 로 부름.

**학습 · 모델**
19. 실패 상자의 제목이 영문 코드 그대로(WorkerLost · ScriptError · Oom …).
20. Seed 가 D-FINE · RF-DETR 에만 전달됨 — 다른 스크립트는 기록만 함. 화면 도움말은 "같은 입력·seed 면 같은 결과".
21. 하이퍼파라미터 칸의 흐린 기본값(서버 목록)이 스크립트 실제 기본값과 다름 (예: YOLO epochs 60 표시 · 실제 100). 매뉴얼은 부록 B 에 둘 다 적음.
22. YOLO · PaddleOCR 스크립트는 사전학습 미러(폴더 경로)를 받는 코드가 없어 보임 — 미러를 고르면 실패할 수 있음, 시험 필요.
23. 버전 상세의 [검증] 이 늘 "미실행" (채우는 코드 없음).
24. 모델 계열 보관은 API 로만 가능 — 화면에는 "보관된 모델" 거르기 스위치만 있음.
25. 감사 로그를 보는 화면 · API 가 없음 (사유는 스테이지 이력 · 바인딩 이력에서만 보임).
26. 사전학습 [자산 삭제] 에 확인 창이 없고, 쓰는 학습이 있는지도 보지 않음.
27. 대시보드 "진행 중인 학습" 이 최근 20건 안에서만 셈.

**계정**
28. 운영 웹 없이 설치한 서버(Local 모드)에서 비밀번호 변경 화면으로 가는 메뉴가 없음 (주소 /change-password 직접 입력).
