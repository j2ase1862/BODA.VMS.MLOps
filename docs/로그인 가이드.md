# BODA VMS MLOps 로그인 가이드

문서 버전 v1.0 (2026-09-11) · 대상: MLOps 관리 화면을 쓰는 엔지니어·관리자

MLOps 에는 따로 만든 계정이 없습니다. **운영 웹(BODA VMS Web)에서 로그인해 받은 토큰**을 MLOps 로그인 화면에 붙여 넣어 들어옵니다.
두 서버가 같은 서명 키를 쓰기 때문에 운영 웹의 토큰이 그대로 통합니다.

## 1. 누가 들어올 수 있나

운영 웹 계정의 역할에 따라 MLOps 에서 할 수 있는 일이 정해집니다.

| 운영 웹 역할 | MLOps 에서 | 할 수 있는 일 |
|---|---|---|
| Admin | 관리자 | 모든 일. Production 승격·Retired, 워커 발급, 사전학습 미러 관리 |
| User | 엔지니어 | 모델·데이터셋 등록, 라벨링, 학습 제출, Staging 승격, 레시피 바인딩 |
| Guest | 조회 | 보기만 |
| (그 밖) | — | 들어올 수 없음 |

라인 작업자는 운영 웹 계정이 없으므로 MLOps 에도 들어오지 않습니다. 권한을 바꾸려면 운영 웹의 사용자 관리에서 역할을 바꿉니다.

## 2. 토큰 꺼내기

운영 웹에는 "토큰 복사" 버튼이 없어서 브라우저에서 꺼냅니다.

1. 운영 웹에 로그인합니다.
2. **F12** 로 개발자 도구를 열고 **Application**(애플리케이션) 탭을 누릅니다.
3. 왼쪽에서 로그인할 때 고른 방식에 맞는 저장소를 엽니다.
   - "로그인 유지" 를 **켜지 않았으면** → `Session Storage` → 운영 웹 주소
   - "로그인 유지" 를 **켰으면** → `Local Storage` → 운영 웹 주소
4. 키 **`authToken`** 의 값(`eyJ` 로 시작하는 긴 글자)을 두 번 눌러 전체를 복사합니다.

토큰은 비밀번호와 같습니다. 메신저·메일로 남에게 보내지 마세요.

## 3. MLOps 에 붙여 넣기

1. 브라우저에서 MLOps 관리 화면(`http://<MLOps 서버>:5310`)을 엽니다.
2. **액세스 토큰 (JWT)** 칸에 붙여 넣고 [로그인] 을 누릅니다.
3. 오른쪽 위에 이름과 역할이 보이면 들어온 것입니다. 운영 웹 User 는 `User, Engineer` 처럼 두 이름이 함께 보입니다.

## 4. 토큰이 만료되면

토큰은 **8시간** 동안 쓸 수 있습니다. MLOps 는 토큰을 스스로 늘리지 않으므로, 만료되면 로그인 화면으로 돌아갑니다.
운영 웹에서 다시 로그인해(또는 운영 웹이 이미 갱신해 둔 값을) §2 대로 꺼내 다시 붙여 넣으세요.

## 5. 들어가지 못할 때

| 화면에 나온 말 | 원인 | 조치 |
|---|---|---|
| 토큰을 읽을 수 없거나 이미 만료되었습니다 | 일부만 복사했거나 8시간이 지났다 | §2 부터 다시. `eyJ` 로 시작해 끝까지 복사했는지 확인 |
| 서버가 토큰을 거부했습니다 (401) | MLOps 와 운영 웹의 서명 키가 다르다 | 관리자에게 알림 — MLOps 설치 때 넣은 Jwt 키가 **이 운영 웹**의 키와 같아야 한다. 운영 웹과 개발 웹은 키가 다르다 |
| 서버가 토큰을 거부했습니다 (403) | 운영 웹 역할이 Admin · User · Guest 가 아니다 | 운영 웹 사용자 관리에서 역할 확인 |
| 워커 토큰(wk_)은 서비스 계정입니다 | 워커 토큰을 붙여 넣었다 | 사람의 토큰(`eyJ…`)을 쓴다 |

## 부록. API 로 토큰 받기 (스크립트용)

```
POST http://<운영 웹>:5292/api/auth/login
Content-Type: application/json

{"username": "…", "password": "…"}
```

응답의 `token` 이 같은 토큰입니다. 운영 웹은 로그인 시도 횟수를 제한하므로 반복 호출에 쓰지 마세요.
PowerShell 5.1 에서 curl 로 보낼 때는 본문을 파일에 쓰고 `--data-binary @파일` 로 넘기세요 (따옴표가 지워집니다).
